## 1. Purpose

This document records the final implementation-freeze audit for Stage 4. The
audit was read-only except for the creation of this document. No features were
added, no working code was refactored, and no protected file was modified.

The objective was to confirm that the current implementation still satisfies the
Stage 4 safety and determinism requirements before a controlled demonstration.

## 4. Implementation checks

A read-only runtime probe and source inspection were used to verify each
required invariant.

| Requirement | Finding | Result |
| --- | --- | --- |
| All six verification decisions exist | `VERIFICATION_STATUSES` is exactly `MATCH`, `PARTIAL_MATCH`, `MISMATCH`, `NO_MATCH`, `INSUFFICIENT_INFORMATION`, `MANUAL_REVIEW_REQUIRED` | PASS |
| Catalogue matching remains deterministic | 40 rows, six preserved source columns, exact indexes, stable row-number tie-break, read-only SHA-256 tracking | PASS |
| Registration numbers are never fuzzy-matched | `registration_key()` only normalises case/hyphen glyphs; fuzzy retrieval is suppressed whenever a registration number is present; field comparison is exact-only | PASS |
| Generic-name collisions do not produce arbitrary matches | Every matching product is retained; `Paracetamol` returns two candidates and `MANUAL_REVIEW_REQUIRED`; no first-row selection | PASS |
| Manufacturer is never inferred from applicant | Loader reads `manufacturer` only; blanks become `None`; field comparison explicitly refuses `applicant_name` substitution | PASS |
| Package volume is never confused with strength | Separate parsers and fields; `100 ml` is valid volume and unparsed strength | PASS |
| OCR observations are not ground truth | All results set `accuracy_tested=False`; notes state OCR values are observations only and accuracy is `NOT TESTED`; ground truth remains empty | PASS |
| Conflicting observations trigger manual review | Conflict branch returns `MANUAL_REVIEW_REQUIRED`; `pack_10` retains both original values and is flagged for `brand_name` | PASS |
| No emitted result claims unsupported certainty | Results use the six deterministic statuses, human-readable reasons and explicit limitations; no authenticity/regulatory claim is generated | PASS |
| No numeric confidence/probability assurance is emitted | Emitted model dumps contain no confidence or probability field, no percentage, and no such wording; fuzzy values are named `similarity_score` only | PASS |

## 6. Completed capabilities

The frozen implementation provides:

- read-only loading and validation of the six-column local catalogue;
- exact registration-number, brand-name and generic-name indexes;
- conservative in-memory strength, dosage-form and package-volume derivation;
- a common observation model for SMS, photo OCR and reconciled packaging rows;
- deterministic candidate generation with registration-number priority;
- suppression of fuzzy name suggestions when an unknown registration number is
  present;
- preservation of every product in generic-name collisions;
- seven-field comparison with `MATCH`, `MISMATCH`, `UNKNOWN`, `UNPARSED` and
  `CONFLICT` field statuses;
- exactly six internal verification decisions with human-readable reasons;
- explicit `MANUAL_REVIEW_REQUIRED` handling for conflicts, ambiguity,
  unconfirmed suggestions and unparsed observations;
- OCR safety notes and `accuracy_tested=False` on all verification results;
- sanitised Gemini error kinds without leaking credentials or raw error bodies;
- 41 Stage 4 offline tests integrated into the full suite.

## 7. Known limitations

1. The 40-row catalogue is a deterministic test catalogue, not an authoritative
   regulatory database.
2. Manufacturer is populated in only 5 of 40 catalogue rows; most manufacturer
   checks remain `UNKNOWN`.
3. Strength, dosage form and package volume are derived conservatively from
   free-text brand names and can be `UNKNOWN` or `UNPARSED`.
4. Fuzzy scores are calibrated string-similarity suggestions, not identity
   measures.
5. Current packaging registration numbers do not overlap the catalogue; the
   correct result is `NO_MATCH` or manual review, never a forced match.
6. Ground truth is empty, so real-pack OCR accuracy remains **NOT TESTED**.
7. Backend integration is **NOT APPROVED**;
   `AWAITING_BACKEND_CONFIRMATION = True` remains unchanged.
8. Live Gemini validation is PARTIAL: five controlled operations passed, and
   the expanded batch was stopped at the 180-second limit. This was an
   availability/latency condition, not an exposed code defect.
9. The offline suite has no pytest-native timeout plugin; live testing used
   SDK timeouts, bounded retries and external hard deadlines.

## 8. Remaining dependencies

Before production or full system integration, the following remain external
dependencies:

- backend owner confirmation of the proposed `Findings` contract and status
  mapping;
- independently populated ground truth before any OCR accuracy claim;
- an authoritative medicine registry or approved dataset for real verification;
- completion of the full live Gemini validation under controlled API limits;
- secure deployment-time management of API credentials without printing or
  logging keys;
- user confirmation/edit of OCR-extracted fields before any downstream lookup.

None of these dependencies are resolved by this freeze audit.

## 9. Controlled demonstration readiness

**Ready: YES, for a controlled offline demonstration.**

The project may be demonstrated for:

- deterministic SMS verification against the local test catalogue;
- registration-number priority and exact matching;
- generic-name collision handling;
- the six verification statuses;
- field-level explanations and manual-review routing;
- packaging OCR observations shown as unconfirmed inputs;
- the current packaging outcome of `NO_MATCH` / manual review, with no forced
  matches.

The demonstration must explicitly state:

- catalogue data is not authoritative regulatory data;
- OCR values are observations only and require user confirmation;
- real-pack OCR accuracy is **NOT TESTED**;
- backend integration is **NOT APPROVED**;
- no confidence, probability or percentage is being used as verification
  assurance.

Live Gemini calls, if demonstrated at all, must remain bounded, optional and
separate from the offline verification claims.
